# Лабораторная работа 3 — библиотека

Продолжение доменной модели лабораторной работы 2. Стек: Python 3.12, Flask, gunicorn. Репозитории в памяти, без базы данных. Три демонстрационных роли в порядке вкладок и схем: информационная система, библиотекарь, читатель. Классы состояний `Loan` реализуют паттерн «Состояние».

## Запуск через Docker

Установить и запустить Docker Desktop (Windows/macOS) или Docker Engine с Compose (Linux). Распаковать архив. Из корня проекта:

```sh
docker compose up --build
```

Открыть http://localhost:5000. Готовность: http://localhost:5000/health.

Остановить: `docker compose down`. При перезапуске приложения данные в памяти очищаются. Для другого порта скопировать `.env.example` в `.env` и изменить `HOST_PORT` (например, на 5001). Сервис работает с одним worker, иначе разные процессы получат разные данные в памяти. Для первого скачивания базового образа и зависимостей нужен интернет. Работа после сборки локальная.

Контейнерная конфигурация подготовлена и проверена структурно. Реальные проверки выполнялись через gunicorn и curl; сборка и запуск Docker в среде выполнения не проверялись, поскольку Docker отсутствует.

## Запуск без Docker

Нужен Python 3.12 или новее. Для запуска в Windows открыть `START_WINDOWS.bat`.
В macOS/Linux выполнить `sh start.command` из папки проекта. Эти файлы создают
виртуальное окружение, устанавливают зависимости и запускают сервер.
После появления адреса открыть http://127.0.0.1:5000. Остановка — Ctrl+C.
Если порт занят, после установки зависимостей запустить `python run.py --port 5001`.
Проверка без запуска сервера: `python run.py --check`.


```sh
python -m venv .venv
# Windows PowerShell: .venv\Scripts\Activate.ps1
# macOS/Linux: source .venv/bin/activate
python -m pip install -r requirements.txt
python -m flask --app wsgi:app run --port 5000
```

Для Linux/macOS сервер gunicorn: `gunicorn --workers 1 --bind 0.0.0.0:5000 wsgi:app`.

## Правила и допущения

- При бронировании экземпляр исключается из доступного остатка. При выдаче остаток повторно не уменьшается.
- При отсутствии свободного экземпляра заявка ожидает в очереди FIFO. Освобождение экземпляра активирует бронь следующего читателя.
- Бронь действует три дня Пн–Пт; день создания не учитывается, время суток сохраняется. Государственные праздники не учитываются: производственный календарь не задан.
- Выдача — 14 календарных дней. Возврат в течение даты `due_on` считается своевременным, по правилам `FinePolicy` лабораторной работы 2.
- Продление — один раз на 7 дней, без очереди и до просрочки. При отказе срок не меняется, в журнал добавляется `renewal_denied`.
- Напоминание — за два дня до `due_at`; после продления срок таймера переносится. Напоминания и передача дела — сообщения учебной заглушки, без реальной рассылки.
- Штраф за день просрочки — 15 RUB (сохранён из ЛР2). За повреждение — демонстрационные 500 RUB, задаются через `DAMAGE_FINE`. При обеих причинах суммы складываются.
- Возврат: `return` → две ветви И: `release-stock` и [`inspect` → `assess-fine`] → `close`. Ветви выполняются последовательно в любом допустимом порядке. Закрытие без всех результатов запрещено.
- Через 30 дней после `due_on` невозвращённая выдача передаётся администрации, билет блокируется. `Escalated` — конечное состояние; дальнейшее разбирательство находится за границей процесса.
- Оплата штрафов моделируется успешной заглушкой. Блокировка после передачи дела не снимается оплатой: это отдельное решение администрации.
- Часы — UTC со сдвигом. ISO 8601 без часового пояса трактуется как UTC; рекомендуется явно писать `+07:00` или `+00:00`.
- Таймеры обрабатываются вызовом `/internal/tick`. Непрерывный фоновый планировщик не входит в требуемую учебную реализацию.
- Переключение ролей интерфейса — демонстрация обязанностей, не система авторизации.

## Пример основного сценария

Начальные данные: `book-1`, `reader-1`. Выполнять команды в Bash, Git Bash или терминале Linux/macOS. В Windows PowerShell для обычных запросов использовать `curl.exe`.

```sh
curl -sS -X POST http://localhost:5000/loans -H 'Content-Type: application/json' -d '{"book_id":"book-1","reader_id":"reader-1"}'
```

Скопировать поле `id` в переменную `LID`:

```sh
LID='вставить-id-выдачи'
curl -sS -X POST "http://localhost:5000/loans/$LID/issue"
curl -sS -X POST "http://localhost:5000/loans/$LID/return"
curl -sS -X POST "http://localhost:5000/loans/$LID/inspect" -H 'Content-Type: application/json' -d '{"damaged":false}'
curl -sS -X POST "http://localhost:5000/loans/$LID/assess-fine"
curl -sS -X POST "http://localhost:5000/loans/$LID/release-stock"
curl -sS -X POST "http://localhost:5000/loans/$LID/close"
curl -sS "http://localhost:5000/loans/$LID"
```

Таймер: запросить `reserved_until` через GET и передать его либо более позднее время:

```sh
curl -sS -X POST http://localhost:5000/internal/tick -H 'Content-Type: application/json' -d '{"now":"2030-01-15T10:00:00+00:00"}'
```

Дата должна быть позже текущих часов приложения. Не использовать фиксированную дату для проверки уже запущенного экземпляра, если часы переведены дальше неё.

```sh
python -m unittest discover -s tests -v
```

25 тестов проверяют очередь, даты, штрафы, все запрещённые сочетания состояния и события, защиту состояния, инварианты восстановления и ответы HTTP. Полный протокол 37 реальных запросов curl — `docs/curl_transcript.txt`. Его время выполнения специально переведено в 2030 год; это тестовое время, не фактическая дата выполнения работы.

Редактируемый оригинал — `docs/library_lab3.drawio`, 6 листов draw.io / diagrams.net:

1. Бронирование и выдача.
2. Пользование книгой и таймеры.
3. Подпроцесс продления REN.
4. Возврат и штраф, парные шлюзы AND1/AND2 и OR1/OR2.
5. UML состояний Loan.

Фигуры, подписи и стрелки редактируются отдельно. В отчёт вставлены экспорты этих листов.
Порядок участников: информационная система, библиотекарь, внешний пул читателя (три роли, два пула).
Ссылки А и Б соединяют фрагменты одного процесса; REN раскрыт на листе 3.
T1–T4 прерывают соответствующую задачу ожидания. T2 переводит WR1 через REM в WR2,
T3 переводит WR2 через OV в WR3. Продление сбрасывает reminded и запускает WR1 с новым сроком.

Векторные экспорты — `docs/diagram_1.svg` — `docs/diagram_6.svg`, печатные — одноимённые PNG.
Дополнительная семантическая модель — `docs/library_process.bpmn` (4 представления).
Проверки достижимости, геометрии и 12 сочетаний ветвей возврата — `docs/model_validation.txt`.

## Структура

- `library_app/domain.py` — объекты-значения, агрегаты и классы состояний.
- `library_app/application.py` — задачи процесса, предикаты шлюзов и таймеры.
- `library_app/adapters.py` — репозитории памяти, часы и внешние порты.
- `library_app/web.py` — Flask API и обработчики ошибок.
- `library_app/templates/index.html` — интерфейс трёх ролей.
- `wsgi.py` — точка запуска Docker/gunicorn.
- `run.py`, `START_WINDOWS.bat`, `start.command` — локальный запуск для демонстрации.
- `Dockerfile`, `docker-compose.yml`, `.env.example` — упаковка и настройки.
- `tests/test_process.py` — проверки.
- `docs/` — схемы и результаты.
